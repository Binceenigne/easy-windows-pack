# Vue：异步、响应式与外部实例

仅在遇到相应问题时读取，不是每个 Vue 任务的前置课程。

## 异步状态不能互相覆盖

快速切换筛选、路由参数或搜索词时，旧请求可能晚于新请求返回。优先复用项目已有请求层；否则按需求使用取消信号或请求序号，保证过期结果不更新数据、错误或 loading。取消通常不作为普通业务失败弹出。

watch 回调的 `onCleanup` 可以登记当前请求的清理；`onWatcherCleanup` 是 Vue 3.5+ API 且需同步注册，使用前确认版本与调用时机。异步 watchEffect 只跟踪首次 await 前同步访问的依赖，不靠它猜测全部请求依赖。

不要无差别 deep watch 大对象，先选择具体字段/getter；也不为尚未出现的性能问题加入复杂缓存。读取 DOM 尺寸应等待相应渲染或合适的 flush 时机，而非反复 nextTick 碰运气。

## 原生 JS / WebView 组件桥接

外部实例可用普通局部变量或合适的 shallowRef，避免不必要的深层响应式代理。典型关系是：

```text
onMounted → 在专属 DOM 容器创建一次实例
props/watch → 调用实例提供的 update 等方法
onBeforeUnmount → dispose，释放监听、定时器与观察器
```

同一个 DOM 子树明确由谁管理，Vue 与第三方库不要同时重绘同一批节点。事件先转换为明确的 emits，再让业务层处理。异步创建过程中若已经卸载，应立即释放创建出的实例，而不是保留悬挂资源。

KeepAlive 的停用不等于卸载；只有任务实际使用缓存页面时，再决定在 activated/deactivated 暂停或恢复订阅，不给所有组件默认加入这套处理。

## 按问题选择高级能力

覆盖层需要逃离裁剪上下文时考虑 Teleport，同时保持焦点和关闭行为；大而不常用的功能再考虑异步组件。SSR 代码不要在服务器阶段直接访问 window/document；共享状态也不能跨请求泄漏。

wrapper 的 attrs、事件和多个根节点要明确转发目标，避免输入失去 label、按钮丢失 disabled 或同一监听触发两次。边界修复以实际案例验证，不预先构造一个万能包装器。

涉及资源/并发变化检查一次“快速切换 + 销毁”代表路径；无法运行时明确说明，不能把源码检查当作运行通过。
