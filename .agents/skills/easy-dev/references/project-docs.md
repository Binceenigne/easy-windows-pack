# 项目记忆：index.md 与 design.md

触发：初始化、结构变动、计数、文档冲突或清单变大。日常增量更新遵循主 Skill 即可，不必每次重读本文件。

## 两个唯一入口

`agent.md` 声明宿主项目及两份文档的位置；默认根目录 `index.md` / `design.md`。不要在各个 Skill 副本、模板或示例里维护“另一个项目真相”。已有同名文件若用途冲突，保留原文并由宿主配置专门目录；移动后更新入口链接。

进入开发任务先看摘要和相关记录；大型表用名字/功能检索所需段落，不必全读。新增组件前仍查真实代码，索引不是“没有可复用组件”的充分证据。

## index.md：知道有什么、到哪里复用

按语义实体而非文件数计数：

- 页面：一个独立业务页面/路由视图；同一页面的路由别名不重复计数。HTML 外壳、layout 和测试夹具不是业务页。示例页单独统计。
- 组件：有清晰职责的 UI 单元，可以是 Vue SFC、React 组件或原生工厂函数。一个 JS 文件可提供多个组件；同一组件的大小/颜色变体不重复计数。
- 页面文件不同时计入组件；局部内部碎片无需逐个登记。共享与功能内组件分组，第三方库不逐个计入自研总数。
- hooks、服务、桥接客户端单列；保留主要公开入口和作用，不把整仓符号表抄进文档。

每条保留稳定名称或 ID、真实路径、职责、必要的公开用法/使用方和状态。路径移动更新原记录，删除时移除活动清单；仍在使用的 deprecated 实现计入当前库存并标记，规划项单列。

计数可写“已登记 8 个，覆盖 A/B；全项目总数未知”。只有检查过全部声明范围才写精确总量；未检查部分不能视作 0。已有完整清单后，根据实际 diff 做增减，不在每次任务重新扫描全仓。

## design.md：知道什么才算一致

最小内容：风格摘要、参考依据、主要语义色、token 实现位置、文字/间距/形态、同类控件的家族规则、共用交互与动效约定。数值代码是实现来源，文档描述意图和关键值；不复制 CSS 全文。

标记“已实现 / 已确认待实现 / 提议”。代码事实与目标规范冲突时，分别保留证据并按确认的目标修复，不将未批准的实现漂移直接改写成规范。新增 token 必须有语义，不能因为本次用了某个数值就把它宣布为品牌标准。

## 维护时机与篇幅

同一批相关代码变更内一起改文档：新/删/改名/迁移对应条目，改变职责/API 更新说明，改变设计系统更新规则和来源。与两份文档无关的内部修复不用修改它们；只有真实内容变化才更新日期。

当详细表已经妨碍定位时，将其按功能放入 `docs/ai/index/` 或现有文档目录，根 `index.md` 保留摘要、分组数量和链接；`design.md` 也可链接独立 token/组件规则。不是每个组件一份文档，不预建空目录。

多 agent 协作时明确各自条目，合并前重读被修改的小段，不用旧快照覆盖整份文件。偏好稳定顺序与局部补丁，避免格式化全表带来冲突。实在无法完成写回时，在交付中列明欠缺条目，不伪报已同步。
