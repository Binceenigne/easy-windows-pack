# 按风险验证，不做仪式性自检

触发：公共 API、共享主题、安全/并发或验证受阻。普通任务使用主 Skill 的轻量结束条件即可。

## 选择最小有用证据

| 变化 | 通常足够的检查 |
| --- | --- |
| 文案、局部样式、无行为的文档 | 看相关 diff、语法/链接；有可用界面就查看受影响状态 |
| 一般页面、组件或用例逻辑 | 现有定向测试或局部检查 + 一个主要交互/调用路径 |
| 公共组件、token、共享契约 | 上述检查 + 有代表性的调用方/主题/状态 |
| 权限、数据迁移、安装/重启、并发、平台生命周期 | 覆盖相关边界与失败路径；必要时更广测试，不能凭“轻量”跳过 |

这不是数量上限；宿主 CI、安全要求和用户指定验收仍应满足。检查命令从真实项目配置、文档或脚本读取，不假定项目一定有 `npm test`、`vue-tsc` 或 pytest。

## 停止重复验证

一般一轮检查足够；修复发现的问题后，只重跑相关检查。不要在代码未变时重复同一测试，不默认全仓格式化、全量构建、多轮审计、全站截图或无关性能优化。

检查失败先判断是本次引入、既有问题还是环境限制。解决本次可修问题；与任务无关的缺失工具或旧失败可以明确记录，而不是安装整套基础设施扩大范围。

浏览器预览不能证明 Windows 原生窗口行为；静态阅读不能宣称运行成功。缺乏目标环境时报告“已做 X，未验证 Y”，不伪造通过结果。

## 最小交付

简短说明实现/复用的主要位置、相关文档更新和实际验证；有未解决风险才单列。无需复述每条原则，也不生成自检报告文件，除非用户或项目明确要求。

文档同步属于实现：只核对本次新增/变更的条目与来源，不要求数量盘点或完整扫描。框架内部改动维护对应专题；业务入口或 UI 规则变化才更新 index/design。
