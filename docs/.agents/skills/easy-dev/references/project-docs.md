# 项目文档：docs 中心与摘要

触发：文档初始化、结构变动、迁移或用途冲突。日常增量更新遵循主 Skill 即可，不必每次重读本文件。

## 文档中心与摘要入口

项目路由声明宿主项目与文档用途。本仓库以 `docs/agent.md` 路由框架开发，以 `docs/README.md` 导航专题；`docs/index.md` / `docs/design.md` 面向框架使用者的应用入口与 UI 规则。AI 资源位于 docs 下，根标准入口显式引导读取。技能模板是精简示例，生成器模板以生成器权威来源维护，不在两处复制同一套正文。

按任务选取架构、开发、npm、打包或接口专题。业务页面和 UI 任务再参考应用摘要；框架内部开发无需自动写业务 design/index。不预读全部 Skill 或 docs。新增组件前仍查真实代码，摘要缺条目不代表没有可复用实现。

## docs：维护可执行的开发知识

- `docs/README.md`：文档导航和各页用途，链接摘要及资源旁的类型契约，不重复粘贴正文。
- `docs/development.md`：环境、开发菜单/命令、预览与原生能力边界、构建、日志、产物和故障定位；中英文说明应表达相同约定。
- `docs/architecture.md`：真实目录职责、依赖方向、公开 API/包名边界、迁移映射及分发约定。旧路径仅出现在明确标注的历史映射中。
- npm/Vite 宿主可用 `docs/npm-vite.md` 集中维护 workspace、创建/开发/构建、公共 exports、单源生成与原生打包边界；不在多个 README 复制完整手册。根与包 README 保留各自快速入口并链接专题页。
- npm/Vite 独立验收放 `docs/npm-validation.md`；旧目录迁移的计数、哈希、EXE 与菜单证据保留历史标签。未经当前执行，不填写测试通过数；registry 名称、所有权与发布状态也不能从本地 pack 推断。
- `docs/packaging.md`：应用构建模式、安装配置、CLI、wheel 公共 API、安装与卸载边界。字段和命令以真实 schema/解析器为准。
- 现有专题页：接口、设计细则、集成与验收按职责增量维护。类型声明、必要的资源旁 README 可留原位，docs 负责导航；不强行每组件一文档。
- 文档迁移同时检查 README 链接、目录树、示例命令和 SVG 等图中文字。保留仍有效的 API/托盘等详细说明；不要用精简摘要覆盖使用手册。
- 验收记录保留日期、环境、范围与限制，注明历史记录性质；不能把过往断言数、旧构建或旧推送状态当本轮结果。

## index.md：应用入口

只记录与当前业务有关的少量页面、组件或服务入口、作用和必要链接。尚无业务时写明待用户补充真实应用入口。无需统计数量、全仓盘点或预建空清单。框架的窗口控制器、打包器、npm exports 和迁移路径归对应专题。

## design.md：应用 UI 规则

用少量文字记录目标用户、主题/密度和关键交互。真实业务规则未定时保留简短待填项；有代码或设计稿时链接来源。不要套完整设计系统表格，不把 welcome、框架 token 或临时数值变成应用强制规范。已确认规则与提议区分清楚，只在业务 UI 约定改变时维护。

## 维护时机与篇幅

同一批相关代码变更内维护受影响的专题；业务入口或 UI 规则变化才改对应摘要。内部修复不触发业务摘要更新；只有真实内容变化才更新日期。

摘要保持简短，详细内容按功能集中到根 `docs/`。新增详细页面同步 docs 导航；不预建空目录，不为迁移重复保留两份维护正文。

多 agent 协作时明确各自条目，合并前重读被修改的小段，不用旧快照覆盖整份文件。偏好稳定顺序与局部补丁，避免格式化全表带来冲突。实在无法完成写回时，在交付中列明欠缺条目，不伪报已同步。
