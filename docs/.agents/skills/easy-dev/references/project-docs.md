# 项目文档：docs 中心与摘要

触发：初始化、结构变动、计数、文档冲突或清单变大。日常增量更新遵循主 Skill 即可，不必每次重读本文件。

## 文档中心与摘要入口

项目路由声明宿主项目、开发文档中心及摘要位置。本仓库使用 `docs/agent.md`，以 `docs/README.md` 为导航，摘要为 `docs/index.md` / `docs/design.md`。AI 资源位于 docs 下，根标准入口显式引导读取，不能假定工具自动发现 Skill。不要在各个 Skill 副本、模板或示例里维护“另一个项目真相”。宿主已有明确布局或同名文件用途冲突时，保留原文并由项目路由说明对应关系。

进入开发任务先看摘要和相关记录，再按 docs 导航选取本任务的详细文档；大型表用名字/功能检索，不必全读。不预读全部 Skill 或 docs。新增组件前仍查真实代码，索引不是“没有可复用组件”的充分证据。

## docs：维护可执行的开发知识

- `docs/README.md`：文档导航和各页用途，链接摘要及资源旁的类型契约，不重复粘贴正文。
- `docs/development.md`：环境、开发菜单/命令、预览与原生能力边界、构建、日志、产物和故障定位；中英文说明应表达相同约定。
- `docs/architecture.md`：真实目录职责、依赖方向、公开 API/包名边界、迁移映射及分发约定。旧路径仅出现在明确标注的历史映射中。
- npm/Vite 宿主可用 `docs/npm-vite.md` 集中维护 workspace、创建/开发/构建、公共 exports、单源生成与原生打包边界；不在多个 README 复制完整手册。根与包 README 保留各自快速入口并链接专题页。
- npm/Vite 独立验收放 `docs/npm-validation.md`；旧目录迁移的计数、哈希、EXE 与菜单证据保留历史标签。未经当前执行，不填写测试通过数；registry 名称、所有权与发布状态也不能从本地 pack 推断。
- 现有专题页：接口、设计细则、集成与验收按职责增量维护。类型声明、必要的资源旁 README 可留原位，docs 负责导航；不强行每组件一文档。
- 文档迁移同时检查 README 链接、目录树、示例命令和 SVG 等图中文字。保留仍有效的 API/托盘等详细说明；不要用精简摘要覆盖使用手册。
- 验收记录保留日期、环境、范围与限制，注明历史记录性质；不能把过往断言数、旧构建或旧推送状态当本轮结果。

## index.md：知道有什么、到哪里复用

按语义实体而非文件数计数：

- 页面：一个独立业务页面/路由视图；同一页面的路由别名不重复计数。HTML 外壳、layout 和测试夹具不是业务页。示例页单独统计。
- 组件：有清晰职责的 UI 单元，可以是 Vue SFC、React 组件或原生工厂函数。一个 JS 文件可提供多个组件；同一组件的大小/颜色变体不重复计数。
- 页面文件不同时计入组件；局部内部碎片无需逐个登记。共享与功能内组件分组，第三方库不逐个计入自研总数。
- hooks、服务、桥接客户端单列；保留主要公开入口和作用，不把整仓符号表抄进文档。

每条保留稳定名称或 ID、真实路径、职责、必要的公开用法/使用方和状态。路径移动更新原记录，删除时移除活动清单；仍在使用的 deprecated 实现计入当前库存并标记，规划项单列。

计数可写“已登记 8 个，覆盖 A/B；全项目总数未知”。只有检查过全部声明范围才写精确总量；未检查部分不能视作 0。已有完整清单后，根据实际 diff 做增减，不在每次任务重新扫描全仓。

## design.md：知道什么才算一致

最小内容：风格摘要、参考依据、主要语义色、token 实现位置、同类控件的家族规则、共用交互与动效约定；文字/间距/形态只写已核实内容。详细规则放 docs 并链接，不保留空表和“待初始化日期”等模板占位。数值代码是实现来源，文档描述意图和关键值；不复制 CSS 全文。

标记“已实现 / 已确认待实现 / 提议”。代码事实与目标规范冲突时，分别保留证据并按确认的目标修复，不将未批准的实现漂移直接改写成规范。新增 token 必须有语义，不能因为本次用了某个数值就把它宣布为品牌标准。

## 维护时机与篇幅

同一批相关代码变更内一起改受影响的 docs 页面及摘要：新/删/改名/迁移对应条目，改变职责/API 更新说明，改变设计系统更新规则和来源。与文档无关的内部修复不用修改它们；只有真实内容变化才更新日期。

摘要保持简短，详细内容按功能集中到根 `docs/`，`docs/index.md` 保留摘要、必要的分组数量和链接；`docs/design.md` 链接专题设计规则。新增详细页面同步 docs 导航；不预建空目录，不为迁移重复保留两份维护正文。

多 agent 协作时明确各自条目，合并前重读被修改的小段，不用旧快照覆盖整份文件。偏好稳定顺序与局部补丁，避免格式化全表带来冲突。实在无法完成写回时，在交付中列明欠缺条目，不伪报已同步。
