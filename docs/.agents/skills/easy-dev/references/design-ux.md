# 视觉一致性与直觉交互

触发：新页面、布局、样式、交互或主题变化。先读项目 `design.md` 的摘要和当前涉及的 token/组件规则。

## 继承产品，不重复设计产品

选择一个已认可的相邻页面或基础组件作参照；有截图或设计稿时对齐它，但不把无意产生的旧问题当标准。延续信息密度、文字层级、图标风格和色彩语义，不自行切换浅/深色、圆角风格或装饰语言。

没有设计文档时，从真实 CSS/token 与现有界面确认最小基线：主色、表面色、文字色、状态色、间距、字号、控件形态。不知道的标待确认；不要凭空替项目指定紫色、渐变、玻璃风或特定主题。

使用语义 token；值的唯一实现来源仍是样式代码。`design.md` 记录含义、来源和必要的当前值，不复制整张样式表。相同角色保持一致，按钮和输入应像同一产品；卡片与小标签不必拥有完全相同的尺寸或圆角。

## 行为符合预期

- 按钮执行动作，链接导航；不可交互的标签不要看起来可点击。优先原生语义和现有无障碍组件。
- 把未加载、加载中、失败、确实为空和有内容区分开。已有内容刷新失败时通常保留内容并提示，而不是一律清空整个页面。
- 提交提供及时反馈，并防止有害的重复提交；失败保留可恢复输入。前端显示成功应来自真实业务结果，而非动画结束。
- 导航、返回和弹窗关闭方式与项目一致。打开覆盖层后合理管理焦点；关闭后尽可能回到触发位置。
- 破坏性操作根据影响提供确认或撤销；无需给每个普通点击弹确认框。错误说明发生了什么及能如何恢复。
- 可见焦点、键盘操作、可读对比、非颜色唯一提示、窗口缩放和减弱动效是基础。只验证本次涉及的路径，不默认全站审计。

## 布局与动效

保持相关信息邻近、主次动作明确；缩窄窗口时优先调整布局和滚动策略，不靠不断缩小文字塞满。桌面端同时考虑最小窗口与 DPI，而非仅手机断点。

动效用于表达状态和空间关系，可中断、可减弱，不能延迟关键操作或掩盖错误。不强制统一固定毫秒数，优先现有 motion token；无既有值时在当前功能内保守选择，只有通用化才登记为规则。

设计改变后在同一批修改中更新 `design.md` 的相应条目与实现位置。需求中的“目标设计”与“当前已实现”分别标注，不能改文档来掩盖实现偏差。
