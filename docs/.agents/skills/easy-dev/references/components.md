# 组件与样式复用

触发：准备新建、抽取、扩展或迁移 UI 组件。目标是共享正确的职责，而不是“尽可能多拆文件”。

## 创建前的最短路径

先看项目 `index.md` 的组件/样式入口，再在相关目录按用途、交互和名字检索源码。读最接近的实现及一个调用处；索引漏记时补相关项。检索范围不含依赖目录、构建输出或 Skill 示例。

选择顺序是偏好而非审批流程：

- 能满足需求：直接复用，样式也走既有 token/类。
- 属于同一职责：加兼容的 props、slot、事件或语义 variant，不复制一份稍有差异的组件。
- 多处共享相同结构/规则：抽取共同部分，先留在功能内部；多个功能确实共享时再提升。
- 语义不同、现有 API 会因此失控：新建小而清晰的组件，继续复用底层 primitives 和设计 token。

不要求每个组件提交“新建申请”。只有复用取舍不明显时，在实现说明中用一句话交代。共享基础控件可以从一开始建立，不必等待固定次数；一次性简单片段也无需为了潜在复用强行抽象。

## 封装与组合

职责、输入、输出与生命周期清楚，比是否使用 class 更重要。Vue 的 props/slots/emits、React 的 children/context、原生 JS 的工厂函数与 `update`/`dispose` 都可实现封装。

同一按钮的 `size`、`tone` 等正交语义变体合理；几十个相互排斥的布尔参数、传页面名称改变内部结构，说明边界有问题。把不同业务强塞进万能 Card 不等于复用。

公共组件处理布局和通用交互；业务组件处理领域语义；页面做编排。HTTP/桥接请求应放到可定位的服务或状态逻辑中，而不是复制进多个按钮。

## 样式也是共享接口

沿用现有颜色、尺寸、间距、圆角、图标和状态规范。优先组件公开变量、语义 class 与 variant，不用页面选择器侵入别的组件内部。

普通 CSS/SCSS、CSS Modules 或宿主既有方案均可；不为执行 Skill 引入 Tailwind、Sass 或新的 UI 库。重复的同类 class/样式可以抽成组件、token 或 mixin，动态宽度等数据驱动值不必强行 token 化。

更改共享组件时检查有代表性的调用方，特别是默认值和事件行为。新增/删除/移动组件、变更公开 API 或复用范围时更新 `index.md`；确立新的家族规则时更新 `design.md`。
