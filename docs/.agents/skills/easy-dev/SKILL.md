# Easy Dev · 可维护开发

让本次功能成为现有系统的一部分，而不是重新生成一个孤立页面。优先清晰、复用与一致性，不追求文件或组件数量。

## 入口与上下文

- `PROJECT_ROOT` 是本次工作的宿主项目根目录，由项目路由指定（本仓库为 `docs/agent.md`）；不是本 Skill 的目录，也不默认等于终端当前目录。下文 index/design 指路由声明的摘要，不表示文件位于仓库根。
- 先参考项目 `index.md` 的概览和相关条目、`design.md` 的设计摘要与相关规则。路径以项目路由为准，本仓库为 `docs/agent.md`、`docs/index.md` 和 `docs/design.md`。
- 根 `docs/` 是开发文档维护中心，`docs/README.md` 为导航；按任务读取开发手册、架构、接口或设计细则。摘要与 AI 资源也位于 docs；根标准入口显式引导读取，docs 下的 Skills 不依赖工具默认自动发现。
- 然后读即将修改的代码及最相近的已有实现。文档帮助定位，不能代替真实代码检索。
- 本文件中的分片、模板路径相对**本 SKILL.md 所在目录**解析。已读且未变的内容复用当前上下文，不重复加载。
- 遵循用户要求和宿主有效规则。本 Skill 是默认工程约定，不覆盖更高优先级指令，不自行扩大写入、联网或发布权限。

## 开发的四个动作

1. **定位并复用**：创建组件、样式、工具函数或服务前，在索引及相关源码中查找同一职责的实现。优先直接使用，其次兼容扩展，再考虑抽取或新建。查到明确答案即可，不要求反复全仓搜索。
2. **做最小完整实现**：按业务/职责组织，保持依赖方向清楚；页面负责组织，业务规则不塞进展示层，公共组件不反向依赖业务页面。优先组合和明确接口，避免继承树或万能组件。已有健康架构不为套模板而重排。
3. **延续产品语言**：优先已有组件及语义 token，保持同类控件的尺寸、色彩语义、状态和交互一致。加载、失败、空数据应可区分；反馈、键盘焦点和危险操作保护按实际风险处理。
4. **同步文档并收尾**：在同一批相关实现中增量维护受影响的 `docs/` 文档及索引、设计摘要，做与风险相称的验证。不要将文档维护留成未完成的后续承诺。

## 持续维护：不是可选附录

- **`docs/README.md` 与详细文档**：开发环境、命令、目录边界、迁移、接口、设计细则与验收说明集中在根 `docs/`，新增页面补导航。已有对应文档就增量维护，不重复创建另一份手册；类型声明及必要的资源旁说明可保留原位并由 docs 链接。
- **`index.md`**：页面/组件新增、删除、移动、改名，或职责、公共接口、复用范围、关键服务入口改变时，更新对应记录和可核实的分类数量。记录真实路径、作用及复用入口；规划项不计为已实现项。
- **`design.md`**：视觉风格、配色、token、排版、间距、组件家族规则或公共交互约定改变时，同步其当前定义和来源。区分已实现、已确认待实现与提议，不把偶然硬编码升级成设计规范。
- 缺文件时，在首次实施相关开发时用 [索引模板](templates/index.md) / [设计模板](templates/design.md) 建立精简摘要，按实际需要建立 docs 导航及详细页面。先填已确认内容；未盘点写“部分覆盖/总数未知”，移除空占位段落，不能把模板或猜测当现状。
- 无关改动不重写全文、不制造仅日期变化的提交。详细清单按功能放在根 `docs/` 并在摘要链接；数量须说明统计口径和覆盖范围。宿主已有明确文档布局时由项目路由指明对应关系，不无故搬移。
- 路径迁移同时核对命令、链接、目录树与文档图片；保留公开 API 与包名的兼容边界。验收记录注明日期与范围，历史通过不等于本次验证成功。
- 只读咨询不自动改文件。文档不可写时继续许可范围内的工作，并说明待补的具体条目。

## 默认结束条件

功能已按需求实现；新增实现确实经过复用查找；相关文档已同步；选择的检查已给出结果或明确限制，即可交付。一般做一轮有针对性的检查，修复本次问题后只重跑受影响部分。不要自行发起多轮审计、全站截图或全量测试；高风险与宿主既有 CI 要求除外。简短报告改动、复用/文档更新和实际验证，不输出长合规清单。
