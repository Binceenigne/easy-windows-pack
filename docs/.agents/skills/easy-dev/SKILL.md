# Easy Dev · 应用开发

让本次功能成为现有系统的一部分，而不是重新生成一个孤立页面。优先清晰、复用与一致性，不追求文件或组件数量。

## 入口与上下文

- `PROJECT_ROOT` 是本次工作的宿主项目根目录，由项目路由指定（本仓库为 `docs/agent.md`）；不是本 Skill 的目录，也不默认等于终端当前目录。下文 index/design 指路由声明的摘要，不表示文件位于仓库根。
- 按项目路由读取与当前业务有关的应用入口和设计摘要；这套 Skill 服务使用框架开发应用的人，不要求理解或维护框架仓库。
- `docs/` 仅保存 Skill、引导文件、精简的应用 index/design 及图片。入口显式引导读取 docs 下的 Skill，不依赖工具默认自动发现。
- 然后读即将修改的代码及最相近的已有实现。文档帮助定位，不能代替真实代码检索。
- 本文件中的分片、模板路径相对**本 SKILL.md 所在目录**解析。已读且未变的内容复用当前上下文，不重复加载。
- 遵循用户要求和宿主有效规则。本 Skill 是默认工程约定，不覆盖更高优先级指令，不自行扩大写入、联网或发布权限。

## 开发的四个动作

1. **定位并复用**：创建组件、样式、工具函数或服务前，在索引及相关源码中查找同一职责的实现。优先直接使用，其次兼容扩展，再考虑抽取或新建。查到明确答案即可，不要求反复全仓搜索。
2. **做最小完整实现**：按业务/职责组织，保持依赖方向清楚；页面负责组织，业务规则不塞进展示层，公共组件不反向依赖业务页面。优先组合和明确接口，避免继承树或万能组件。已有健康架构不为套模板而重排。
3. **延续产品语言与审美**：优先已有组件及语义 token；使用共享网格与对齐线，保持横平竖直、组件边缘和文字基线对齐，同类控件统一间距与尺寸，以层级和留白组织内容。交互应优雅且符合人类直觉：操作顺序自然、反馈及时，未加载、加载中、成功、失败和空数据状态清晰；键盘焦点可见且顺序合理，返回/取消路径明确，关闭弹窗后恢复焦点。避免突兀的布局跳动和无助于理解的装饰性动效；危险操作保护按实际风险处理。
4. **验证并收尾**：做与风险相称的验证。仅在用户确认的业务入口或 UI 约定改变时局部修正已有摘要；不自动扩充摘要，不生成维护日志。

## 精简应用摘要

- **`index.md`**：只记录用户已确认的业务用途和少量真实入口。未定义业务时保留待填项与前端、宿主、样式链接；不列框架内部模块或数量盘点。
- **`design.md`**：只记录已确认的目标用户、视觉和交互选择。未确定时留待用户填写，不将 welcome、示例配色或布局推导成产品规范。
- 需要初始化时参考 [索引示例](templates/index.md) / [设计示例](templates/design.md)，保持最小内容。普通实现不触发摘要扩写；路径失效或确认的规则变化时只修相关句子。
- 不在 docs 新增框架开发手册、版本状态、发布流程、全仓清单或维护日志；验证结果在交付中简述，不自动写入文档。
- 不重复生成已有正文，不仅为更新日期而改文件。只读咨询不自动改文件；文档不可写时说明具体待补项。

## 默认结束条件

功能已按需求实现；新增实现经过复用查找；必要的摘要句子或链接已修正；选择的检查给出结果或明确限制，即可交付。一般做一轮有针对性的检查，修复后只重跑受影响部分。不要自行发起多轮审计、全站截图或全量测试；高风险与宿主既有 CI 要求除外。简短报告改动和实际验证，不生成维护日志或长合规清单。
