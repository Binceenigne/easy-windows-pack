# Go native host

Use `--titlebar-mode default|minimal|native` (or EWP_TITLEBAR_MODE) to choose the initial chrome. Default/minimal are frameless; native creates a real system caption. Crossing that boundary through the bridge requests a restart with the selected mode.

Windows amd64, Go 1.22+, CGO C/C++17 compiler (MinGW-w64), and Microsoft Edge WebView2 Runtime are required. MSVC alone does not supply the GCC-compatible compiler expected by CGO.

From this directory, `go mod download` then `go build -trimpath -ldflags="-H windowsgui" -o ../output/ewp-host.exe .`. Set `CGO_ENABLED=1`, `CC` and `CXX` to your compiler when it is outside PATH. Linker flags request static C/C++ runtimes; WebView2 Runtime remains an external prerequisite.

The executable accepts `--url <http(s) loopback URL>` OR `--assets <frontend directory containing index.html>`, plus `--title <text>` and `--debug`. Environment equivalents are `EWP_DEV_URL`, `EWP_ASSETS`, `EWP_APP_TITLE`, `EWP_DEBUG=1`. An explicit URL/assets flag overrides the opposite inherited environment setting. Supplying both flags is an error. With neither, production looks for `frontend/index.html` beside the executable, then project `output/frontend/index.html`. Paths are resolved from the caller's working directory when explicitly supplied. `--help` prints usage. Errors exit nonzero; `EWP_HOST_NO_DIALOG=1` suppresses error dialogs for automation.

Production resources use WebView2's `https://ewp.local/` folder mapping. The asset tree must be on a local disk and contain no symlinks/junctions. Only its index document, query and hash routing receive the bridge. Development trusts only the selected loopback origin. Top navigation to other origins, frame navigation, popup windows and browser permissions are blocked. These guards protect documents; application fetch requests are allowed. The WebView2 profile defaults to a writable per-app directory under LOCALAPPDATA; `WEBVIEW2_USER_DATA_FOLDER` can override it.

The bridge exposes `window.ewpNative.call(method, argsArray)` and a fixed `window.pywebview.api` adapter used by the shared window frame. Supported methods: get_window_state, get_window_size, window_action(minimize/maximize/restore/close), native_drag(move or eight resize directions), get/set/toggle_always_on_top, set_window_size(width,height), hide_window, show_window, set_titlebar_mode(default/minimal/native). Sizes are integer physical client pixels, width 320..16384 and height 200..16384; restore before resizing. Errors return `{ok:false,error}`. Requesting native chrome returns `restartRequired:true`, `titleBarMode:"native"`, and the unchanged `activeTitleBarMode`; the launcher must handle restart/configuration. This template starts frameless.

`bridge_windows.cc` uses the public C ABI compiled once by the blank-imported **official webview_go module**, pinned in go.mod. It does not compile a second webview implementation. `include/webview.h` (webview 0.11, commit fb6b17d826041411e6346cd9a785a5ceba7987c4), `include/WebView2.h` (1.0.1150.38), and their LICENSE files are byte-for-byte declaration copies from that pinned module. Their authority is upstream, not the local copies. In the framework repository, `tests/native-backends-build.mjs` verifies all four files against the module before compiling; update the pin and declaration/license copies together. The webview C API is void-returning in this pin, unlike webview 0.12. webview is MIT; the WebView2 SDK carries its supplied Microsoft license. Keep both notices when redistributing these headers.

Native movement/resizing is delegated to Windows through WM_NCLBUTTONDOWN with resize/minimize/maximize styles retained. Maximization uses the monitor work area. Interactive drag, drag-restore and system snap require an interactive desktop for acceptance testing.
