# C++ native host

Use `--titlebar-mode default|minimal|native` (or EWP_TITLEBAR_MODE) to choose the initial chrome. Default/minimal are frameless; native creates a real system caption. Crossing that boundary through the bridge requests a restart with the selected mode.

Windows, CMake 3.24+, a C++17 compiler (MSVC Build Tools + Windows SDK or MinGW-w64), Git, and Microsoft Edge WebView2 Runtime are required. From the generated project root, configure with `cmake -S backend -B backend/build -A x64`, then `cmake --build backend/build --config Release`. The output is `backend/build/ewp-host.exe`. For MinGW use its generator instead of `-A x64`. CMake fetches official webview/webview 0.12.0 (MIT), nlohmann/json 3.11.3 (MIT), and Microsoft's WebView2 SDK 1.0.1150.38; retain upstream license notices when distributing dependencies. No second webview implementation is compiled in main.cpp: WEBVIEW_HEADER imports declarations and webview::core_static supplies the implementation.

Launch with `ewp-host.exe --url <loopback HTTP(S) URL>` for development, or `ewp-host.exe --assets <directory containing index.html>` for production. Optional flags: `--title <text>`, `--debug`, `--help`. Environment equivalents: EWP_DEV_URL, EWP_ASSETS, EWP_APP_TITLE, EWP_DEBUG=1. Explicit --url/--assets overrides the opposite inherited environment value; the two flags are mutually exclusive. With neither, locate frontend/index.html beside the executable or project output/frontend/index.html. Relative explicit paths use the caller's working directory. Failures exit nonzero; EWP_HOST_NO_DIALOG=1 suppresses error dialogs in automation.

Production uses the WebView2 HTTPS virtual host https://ewp.local/index.html, including Vite ES modules and relative assets. Only that index document (plus query/hash routing) is trusted. Development trusts the selected localhost/127.0.0.1/[::1] origin. Other document origins, frame navigation, popups and browser permissions are blocked; application fetch remains available. Asset trees must be local and contain no symlinks/junctions. Profiles use a writable per-app LOCALAPPDATA directory, overridable with WEBVIEW2_USER_DATA_FOLDER.

The fixed window bridge exposes ewpNative.call(method,argsArray) and the pywebview.api adapter used by the existing frame. Methods are get_window_state/get_window_size, window_action(minimize/maximize/restore/close), native_drag(move/left/right/top/bottom/top-left/top-right/bottom-left/bottom-right), get_always_on_top/set_always_on_top(bool)/toggle_always_on_top, set_window_size(width,height), hide_window/show_window, and set_titlebar_mode(default/minimal/native). Success includes ok and window state; errors return {ok:false,error}. Sizes are integer physical client pixels: width 320..16384, height 200..16384. Restore before resizing. Native titlebar requests report restartRequired:true with activeTitleBarMode unchanged; the launcher owns configuration/restart. This host starts frameless.

Windows owns the move/resize loop. Resize/minimize/maximize styles remain enabled for system snap and drag-restore. WM_GETMINMAXINFO constrains maximization to the selected monitor work area. The framework's tests/native-backends-* verification scripts build outside this template and exercise real WebView2/HWND behavior.
